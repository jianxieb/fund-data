## 本次落地

选择“配置工作台 + 可追溯研究库”，项目名改为“长衡”。重建全部七个页面：配置总览、配置实验室、指数观察、基金研究、个股观察、投入策略、数据与方法。数据从旧大体积HTML中移到独立数据文件；更新脚本不会覆盖界面。

配置工具包含目标、人民币持仓、目标权重、现金覆盖、偏离、同指数重复暴露、当前与目标情景对照、两种再平衡方式、固定收益与通胀试算。首次展示明确标记的示例，建立个人配置需要用户保存；不根据历史收益自动生成个人资产比例。

基金按投资范围、风格、管理方式和交易渠道检索，视图可以交叉：扩展研究池中的QDII同样进入海外视图，主动红利基金也进入红利视图；不会再按抓取脚本来源决定分类。基金字段、详情、买入卖出与持续费用复用同一组件。

| 股票 | 23只在线重算，115个收益窗口保留实际基期 | [股票验证](../data/verification-stocks.json)。具体符号、币种、复权字段和报价时间明确；缺少报告期的估值、ROE不使用旧值代填 |
| 投入策略 | 9项ETF × 12种策略，共108项 | 首日现金、现金流中性净值、交易成本、信号时点和残缺年份预算已修正；单一起止窗口与零成本假设仍有限制 |

重要纠错不只涉及展示：004355原五年回撤−12.1%被纠正为−29.258%，已因此退出默认候选；详情见 [同日原始窗口复现](../data/screening-risk-correction.json)。部分十年收益原值也被修正。对应旧年度备注已重算，旧报告已加归档提示。

当前质量报告为 **0项错误、4项提醒、3类待核验**。待核验包括未逐只重算的历史研究池、正式费率生效日和申赎持有期、股票财务报告期。候选中的4只ETF销售服务费仍未知；未知不是0。机器可读结论见 [质量报告](../data/quality.json)。

有基期的前端收益按实际日期跨度年化；缺少基期的旧快照按名义周期估算，并标明日期未独立记录。波动年化因子沿用已验证来源约定并在“数据与方法”披露，不能作精细跨来源排名。

## 浏览器实际验收

使用本地HTTP服务，在桌面1280像素与手机390 × 844视口操作。确认过以下真实页面行为：

| 流程 | 验收结果 |
| --- | --- |
| 指数 | 上证展示自身收益、回撤和官方来源；纳综与纳指100不同；人民币切换显示重算收益，缺失日风险给出原因 |
| 基金 | 22只默认候选、完整1314只分页、搜索无结果与清除、筛选、排序、详情、红利费用统一、四只对比上限生效 |
| 分类 | 扩展池QDII进入海外范围；主动红利进入红利范围；混合或跨市场产品加入配置时保留待分类 |
| 策略 | 已有资金与后续收入分开；月/季/年基础定投均投入199000美元，倍数策略显示不同预算；杠杆需主动展开 |
| 表单 | 目标权重90%明确阻止保存，100%通过；修复了原生数字步进导致默认5个百分点不能提交的问题 |
| 保存与恢复 | 本地测试配置30万元保存后刷新恢复；名称中的尖括号按文本显示；导出JSON与导入对象逐字段相同 |
| 清空与导入 | 畸形JSON被拒绝；有效文件先进入复核表单；清空后返回示例；实际导出文件重新导入恢复成功 |
| 情景 | 当前/目标采用同一规模；清空冲击输入时金额和比例留空；零资产显示“先录入持仓”，没有虚假绿标或NaN |
| 再平衡 | 示例80万元新增3万元：仅新增模式无卖出，净变化30000元，调整后830000元；允许买卖模式回到目标比例 |
| 目标试算 | 80万元、每月3000元、10年、4%收益/2%通胀的结果与模型相符；0%、负收益和通胀假设由模型测试覆盖 |
| CSV下载 | 浏览器实际导出一行050025基金结果及六类资产计划；文件解析后确认金额守恒、无意外卖出 |
| 键盘与响应式 | 弹窗Escape关闭并返回触发按钮；指数页签方向键可用；390像素整页宽度390，表格在自身352像素容器内滚动；手机编辑弹窗无横向溢出 |

浏览器下载事件接口没有报告JSON下载完成，但文件已实际落盘；随后读取文件核对并完成导入恢复。测试下载已移入本机临时验收目录，测试个人配置已清空。

本地file协议受验收浏览器的URL策略限制，未做file://页面操作验证；交付入口使用已验收的本地HTTP服务。Windows调度脚本在代码层面检查，本次没有Windows运行环境，不宣称已在Windows执行。

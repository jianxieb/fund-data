# 数据与更新链路审计

审计日期：2026-09-21。计算正确性、来源完整性、日期新鲜度和独立资料核验分别记录。结构检查通过不代表每一个历史数字已独立核实。

## 已发现并修复的问题

| 问题 | 影响 | 现行处理 |
| --- | --- | --- |
| USD/CNY 使用期初/期末 | 人民币收益的汇率贡献方向相反 | 使用 `美元资产倍率 × 期末美元兑人民币 / 期初美元兑人民币`；各资产保存真实价格与汇率端点，不混用CNH，不沿用旧窗口汇率 |
| 外汇日线用UTC日期归类 | 伦敦夏令时午夜变成前一天，造成星期日行情、星期五缺行及人民币窗口取错端点 | 重新取得Yahoo原始时间戳，按返回的`Europe/London`交易时区归一化；v3缓存保存原始时间戳和日期规则，拒用旧外汇缓存 |
| 纳综与纳指100五个收益完全相同 | 不同指数串线 | 以Yahoo明确符号 `^IXIC`、`^NDX`重新取得行情；相同长路径会被拒绝 |
| ETF复权源失败后退到未复权价格 | 拆分和分红造成虚假收益 | ETF必须提供明确复权字段；新浪备用源仅限价格指数 |
| 把累计净值之比称为红利再投资 | 分红复投与拆分混淆 | 用单位净值、可完整识别的分红表与拆分表链式复权；无动作证明时只接受供应商明确每日收益，缺失则拒绝 |
| 根据净值跌幅猜是否分红 | 分红当日市场涨跌可能使猜测失效 | 明确除息现金与拆分比例；不按跌幅判断动作 |
| 150个点就展示“三年风险” | 短样本被包装成长周期 | 要求完整日历窗口和每年至少200个观测；3年、5年分别计算并保留真实基期，不把3年风险放到5年列 |
| 分批策略把期初资金当未来入金 | IRR忽略闲置资本；仓位与回撤错误 | 10万美元期初全部入账；分批买入从现金扣除；定投才作为外部贡献 |
| 扣交易成本后现金为负 | 回测发生无意借款 | 成交金额按交易成本约束；负现金是计算错误，直接失败 |
| 月/季/年定投在残缺年份预算不同 | 期末金额无法比较 | 按共同样本包含的月份统一基础预算；倍数定投仍明确资金投入不同 |
| 第三方 `close`直接标为Yahoo复权价 | 无法证明包含拆分/分红 | 直接使用Yahoo chart `indicators.adjclose`并核对标的身份；旧缓存不被接受 |
| 股票把未来除息算进已收股息 | 股息率被高估 | 只纳入除息日不晚于报价日的已实施分红；报价保存时间戳 |
| 分红年数从2021写死 | “近5年”随时间变成6年等 | 明确最近5个已结束报告年度，显示具体窗口 |
| 日更只更新一类数据并自动push | 页面各板块滞后、运行成功被误认为整体新鲜 | 跨平台入口覆盖所有数据集；源失败/超时非零退出；不执行Git提交或推送 |
| 更新脚本直接改网页 | 数据与界面互相覆盖 | 所有数据更新写`data/snapshot.js`或独立JS/JSON数据文件 |

## 实际数据验证

- **海外基金**：46只已取得完整原始历史及动作表并重新计算所需1/2/3/5/10年窗口，14只具有可比较的完整5年风险；其他记录保留历史不足或跨策略转型的明确状态。原始历史缓存位于 `.tmp-hist`，分红/拆分与申购页位于 `.tmp-fhsp`。`096001`的2015-01-19源净值为空，属于最长请求窗口以外；没有把空值填零或编造净值，计算只从所需的2016年基期开始。
- **海外基准**：9项已使用真实指数/ETF复权序列重新计算，另取 `CNY=X` 进行人民币换算。每项保存来源、真实截止日期与各窗口的资产/汇率起止日期，9项美元5年风险均可用。人民币5年风险要求逐个资产交易日有真实同日汇率；修复时区后，原始源仍在2025-04-21返回空值，因此全部9项人民币日风险留空，并记录`incomplete_fx`、所缺日期与所需基期。
- **外汇原始证据**：`data/verification-fx.json`保存原始响应SHA-256、交易时区、选定时间戳及修正前后的人民币收益。例如`1789686000`在UTC是2026-09-17 23:00，在伦敦是2026-09-18 00:00；不能把这条9月18日观测当成9月17日。修正后5年窗口的缺失汇率由148个资产交易日缩小到1个真实源缺值；没有人为补行或填充。
- **策略**：9项ETF × 12种策略共108项，用明确复权字段与修正后的现金账户重新计算。共同可用日期写入`STRATEGY_META`，不会把请求日期冒充成交日期。
- **代表样本**：`data/verification-samples.json`保存050025、160213、513500、539001、512890的关键原始行、所有企业动作、窗口基准日、重算结果与归一化完整历史SHA-256。官方动作检查只覆盖明确列出的事件，不扩大为全历史独立审计。
- **国内指数和国内基金筛选**：独立管线的结果、来源与限制见`data/indices.js`、`data/screening.js`及相应审计文件。
- **股票**：旧东方财富/腾讯历史源返回不足或断开；先实测600900，再以Yahoo明确标的、CNY币种及adjclose字段完成23只全部重算，52.9秒成功。保存明确来源与实际报价时间；股息由已实施分红记录计算。股票ROE/估值报告期不明，缺失基本面留空，不将旧值混入新报价。

## 运行与故障行为

```sh
python3 -m pip install -r requirements.txt # IANA时区数据，尤其供Windows使用
python3 refresh.py                         # 全部数据集；每项默认限时180秒
python3 refresh.py --offline               # 严格缓存回放，不联网
python3 refresh.py --datasets indices,quality
python3 refresh.py --datasets funds --timeout 60
python3 verify_samples.py                  # 5项代表数据与原始证据
python3 verify_samples.py --offline
python3 -m unittest discover -s tests -v
```

Windows使用`daily_update.ps1`调用相同Python入口。它不会创建或更改系统调度，也不进行Git提交/推送。旧的`-NoPush`参数保留兼容但不再有自动发布路径。

每次刷新生成`data/refresh-report.json`与浏览器可直接读取的`.js`，每个子任务日志写入`.tmp-snap/refresh-<dataset>.log`。`data/update-status.json/.js`保存最近执行状态；`data/quality.json/.js`保存内容质量。一次命令完成与源数据准确、最新是不同结论。

缺失、缓存回退、超时都保留实际观测日期。没有缓存的离线更新返回非零码，不能伪报刷新完成。页面保持可用并展示缺项。单个上游失败不阻断其他数据集刷新，最终入口以非零码明确部分失败。

## 验证与未覆盖范围

回归覆盖分红复投、拆分、累计净值拒用、完整风险窗口、汇率方向、伦敦夏令时与冬令时日期、无时区证明的外汇缓存拒用、逐日人民币风险与缺汇率拒算、重复指数路径、闲置现金、现金流中性回撤、交易成本约束、残缺年份预算、信号次日执行、未来分红过滤和离线网络边界。

5年风险使用日对数收益的样本标准差乘以`√250`，回撤包含窗口初始价格。基金字段为`vol5/mdd5/risk5First/risk5Status`，`riskFirst`对应5年窗口；原3年风险仍保存在`v3/mdd3/risk3First`。基准分别输出`riskUSD5`与`riskCNY5`，附实际起止日期、观测数、年化日数和状态；人民币风险没有复用美元风险。

历史回测仍是单一起止窗口，存在起点偏差；未建模税费、跨境汇兑成本和现金收益。倍数定投的投入预算不同。数据商历史可能修订；正式费率的生效日期、股票基本面报告期和未抽样国内基金数据仍在质量报告中明确列为待核验，不能把“可计算”当作“独立验证”。

本次最终执行结果：46只海外基金、23只股票、9项海外基准与108项策略结果均重新计算。股票首次在线尝试因旧源故障显式失败；增加并验证第三源后，23只在52.9秒内全数通过。全部六类数据离线回放返回0。最近在线尝试被单独保存，离线回放不会覆盖它。

# 组合投入方法研究：2026-11-05

本目录记录实际运行的试验、参数、全部结果及复现材料。当前现金补仓规则在前一共同收盘锁定各标的金额，下一共同收盘执行；本页现金主表全部使用该版本。旧 `cash-results.*` 与旧 `reproduction.tar.gz` 保持不变，只记录被替换的“成交收盘重新定额”版本，不能再引用为当前规则结果。新证据使用 `executable-*` 文件。

现金补仓将原现金转为股票持有，没有回撤阈值、冷却参数、卖出或额外注资。它提高了指定历史的终值，也提高了风险暴露；不能称作已找到预测买点的同风险 alpha。

系统已接入 `现金补足目标仓位`（cash_topup）与 `QQQ深熊确认调仓`（qqq_bear_confirm）。两者用途不同：前者会动用原现金，后者只让 TQQQ 对应资金池在持有与现金之间切换，不挪用原 40% 现金配置，也不替其他股票择时。

## 当前现金订单怎样形成与执行

在共同收盘后，以已知税前账户总值 V、股票／ETF／基金市值 K、现金 C、目标合计 W 及单侧费率 f 计算 `B=max(0,min(C/(1+f),(W*V-K)/(1+W*f)))`。按每标的正缺口 `D_i=max(0,w_i*V-K_i)` 分配固定金额 `B_i=B*D_i/ΣD_i`，连同费用一起留出现金。下一共同收盘只按价格换算份额，不因当日涨跌重新限额或撤单；因而成交后可能超过目标权重。

执行日先处理持仓分红税，再执行已承诺的固定订单，然后处理本日入金、原投入计划及周期再平衡，日终形成下一笔计划。新入金不扩大昨日订单，再平衡不抢占已承诺现金；同一时间只有一笔待单。初始日没有未知的前日订单，末日实际清仓会跳过待单。生产的 `nextTopupPlan` 是尚未成交的固定金额，`topupSignalDay` 是最后检查计划的共同收盘；较晚汇率估值日不冒充信号日。研究额外延迟一天的压力条件使用第二个共同收盘成交，等待中不再立新单，因此同时改变成交延迟和规划频率。

确认趋势规则在 ETF 样本中只有 2022 年一次退出/恢复事件；众多重叠窗口不能当作许多次独立成功。其外部二十年结果采用不同真实基金且仅零税，详包内 risk-confirm/external-results.json。

QQQ规则不锁定30/30：固定参数改用USD/TQQQ 50/50、无初始现金，在0.10%费用、20%资本利得及股息税下，十年／十五年年等权CAGR差为+0.5044249／+0.2665205 pp，胜／平／负分别52/28/1与21/0/0。该配置的现金补仓与一次性投入持平，QQQ调仓仍依据退出和回归信号交易；这里没有重新选参。[满仓逐账户证据及独立核验摘要](qqq-fully-invested-evidence.json)保留来源路径和审计对应模型哈希。

QQQ历史曲线记录已经执行的状态；`qqqNextSignal` 按最后共同收盘形成下一共同日实际执行指令，`qqqLatestSignal` 只表示截至模拟末日最新QQQ观察。不同市场日历下两者可以不同，较新观察不能冒称下一日必执行的指令；清仓完成不再返回下一指令。

各阶段存在重复历史研究及后续探索，不把这些计数加总成独立验证次数。所有失败、持平、负收益差的已完成试验均留档；前轮撤回的旧评分历史仍在原目录，本目录不改写原档案。

## 文件与核验

- `executable-summary.json`：当前固定金额订单规则的100格汇总与风险。全部84格平均正、16格零、0格负；重复起点／条件累计4132胜1072平，不是独立验证次数。
- `executable-results.csv`：当前规则5204个配对账户（4896个ETF、308个外部基金），含规则、一次性及旧成交收盘版本的收益、风险、税费与订单数据，未删平局。
- `executable-results-columns.json`：77列的字段、单位和空值说明；CSV已完成5204行全字段回读核对。
- `export-executable-csv.py`：从新包 `results.json` 重建CSV与字段说明，不改变冻结研究结果。
- `qqq-fully-invested-evidence.json`：从旧QQQ研究包提取的50/50满仓81个十年及21个十五年配对账户，另含四权重默认汇总、满仓16个压力格及独立账本审计摘要；不是对当前新字段的重新生产审计。
- `executable-reproduction.tar.gz`：当前规则的冻结输入、协议、完整结果、四条逐日轨迹、因果与独立账本核验、生产快照和重现器；内部根目录为 `entry-executable/`。
- `cash-results.json`、`cash-results.csv`：旧成交收盘重新定额版本的100格、5204对账户，仅作版本记录。
- `reproduction.tar.gz`：旧现金版本及各轮买入／QQQ研究的原冻结协议、代码、选择和结果；字节保持不变。QQQ研究数值仍以此包相应记录为依据，不把旧现金执行规则移用于当前生产。
- `manifest.json`：归档及每个成员的字节数、SHA256、CSV 行数/哈希。
原 risk/evaluation.json 内指向的 91,455,214 字节逐日决策账本没有重复打包；所有逐账户结果、参数及逐日曲线 SHA256 均已保留，可用 `replay.py risk` 从相同代码/行情重建完整结果。manifest 记录被省略原压缩账本的哈希；这是明确省略可重建的明细，未删除任何候选的收益结果。

当前规则由独立JS账本复算10,408条策略／基准记录，终值最大误差5.46e-12。生产模型另核对未额外延迟的2,448对、4,896个账户，覆盖六权重、两费率、两税率；终值最大误差7.28e-12、税储备最大误差1.37e-12，22,409笔补仓逐笔核对前共同收盘信号日和成交日。四条完整轨迹、107个计划快照、单笔待单现金约束、反弹仍执行原金额及未来行情／分红扰动均保留。额外延迟和外部基金不伪称生产支持；不再验证或宣称成交后不超目标。

这些检查确认冻结数据上的因果顺序与计算一致，不等于拥有每个历史日当时发布的数据档案，也未实测具体券商整股／碎股订单限制和额外实际滑点。旧现金版本的审计仍封存在旧包，并标记对应模型哈希。

QQQ 方法另有 408 个配对账户（816 条策略/基准记录）的生产核验：终值、CAGR、MDD、已缴总税/资本利得税/分红税、税准备金及交易费均与归一化研究账本一致，408 组 TQQQ 信号/成交日期也一致。原研究分池扣初始手续费，生产则整体扣费，核验仅用 g=(1+fee)/(1+fee×股票目标合计) 归一化初始资金，不改用户权重或规则。两份 production 审计及其对应模型 SHA256 完整保留在 risk-confirm/。

## 相对路径复现

要求Python 3与Node.js，无第三方运行库；无需抓取新行情。当前现金版本使用独立新包，解压后在不存在的新输出目录重算：

```sh
tar -xzf executable-reproduction.tar.gz
python3 entry-executable/replay.py --destination entry-executable/rerun
```

启动器重算核心结果、全部100格、轨迹与因果验证、独立JS账本及生产审计，并比较七个输出的SHA256；已有目标目录会明确拒绝覆盖。冻结生产快照的哈希以新包审计与清单为准。

在本目录解压后，也可用导出脚本从冻结结果重建CSV及字段说明；输出写在所给源文件的同一目录：

```sh
python3 export-executable-csv.py entry-executable/results.json
```

以下命令仅重现旧现金版本与其余历史研究，不能用其旧现金输出替代上方新结果：

```sh
tar -xzf reproduction.tar.gz
python3 research/replay.py cash
```

旧包曾实际解压并执行 `cash`，七个输出与该旧版本冻结结果逐字节一致；这是旧版本复现证据。新旧生产模型SHA分别保留，不混称同一实现。
`cash` 重算全部费税/权重/延迟格、不同基金税前二十年扩展、自检与生产账本核验，输出在 `research/rerun/cash/`。目录已经存在时拒绝覆盖，可加 `--destination research/rerun/cash-again`。

其余完整阶段分别运行：

```sh
python3 research/replay.py buy
python3 research/replay.py rebalance
python3 research/replay.py risk
python3 research/replay.py risk-daily
python3 research/replay.py external-risk
python3 research/replay.py risk-confirm
```

也可使用 `python3 research/replay.py all`。原研究脚本与原结果保持字节不变；运行器仅在新副本中把生产审计脚本原机器绝对 import/模型读取路径适配为随包模型的相对路径。某些历史选择记录带运行时间戳，重新执行后的输出哈希可能不同，数值及冻结规则应一致。原结果真实性以 manifest 内哈希为准。

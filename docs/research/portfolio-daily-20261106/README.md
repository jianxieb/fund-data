## 这些状态实际算什么

| 方法 | 每日输出 | 含义 | 对已有持仓的作用 |
|---|---|---|---|
| VIX恐慌恢复调仓 | 持有状态／退出状态 | 依据VIX与VIX3M历史确认条件维持的持仓开关 | 状态切换时退出或用其专属现金买回TQQQ |
| 三批相对强弱轮动 | USD、TQQQ两个分配百分比，合计100% | 两只ETF合计股票预算 | 复核后联合目标变化才调仓；保留三个批次的记忆 |
| 双重风险门调仓 | 持有状态／退出状态 | VIX和QQQ两扇风险门的逻辑与 | VIX、QQQ任一门退出便退出；两者恢复才买回 |

风险开关仍保留0／100作为内部状态编码；它不是百分比分数。轮动百分比的分母是两只ETF合计股票预算。用户可修改原权重；新增预算工具只计算这笔钱按既有配置分配时的买入额、手续费与现金，不改变历史资金流。

页面的“本日怎么算”使用实际参与判定的源数值、条件和连续计数，包括触发后归零之前的次数。轮动保留504个收益间隔的四个价格、日期、三批方向及各批最近复核记录，不能仅凭当前强弱倍数重建既有持仓。

## 100%天数不等于买入次数

[真实账本核对](state-claim-audit.json)使用2014-01-02至2024-01-02、初始10万元人民币、USD／TQQQ各30%、现金40%、不追加、不再平衡、单侧费0.10%、资本与股息税20%、不清仓的配置：VIX有2517个共同交易日，其中2501天为持有状态，但初建后仅2020-03-10卖出、2020-04-01买回一次TQQQ。账户总入金为1笔10万元。

本例策略年化31.25%，同配置一次性投入29.05%；年化按实际现金流中性净值计算，没有在2501个持有日重复追加。预览预算不计入该收益。其他配置按模拟的实际入金和交易计算，不能沿用这个例子的次数。

```sh
node docs/research/portfolio-daily-20261106/verify-state-claims.cjs /tmp/state-claim-audit.json
```

该脚本读取当前保存行情、记录来源指纹并列出全部真实交易。它核对状态与账本，不检验买点预测能力。

每日记录对应实际共同收盘，保留每项来源日期；无新订单的日期也有状态。缺数据时不产生状态结论或预算；轮动预热时分配状态尚未形成，预算明确回退原配置；期末清仓后不产生下一笔投入。首次建仓方式沿用原研究。

使用“延续到最新行情”会保留原跟踪起点、配置与轮动批次演变，只延长结束日期。修改参数后须先重新模拟。CSV保留每个共同交易日的原始数值、完整元数据和预算；组合PDF冻结导出时所选日期与预算。

## 验证与复算

[verification.json](verification.json)保存最终源码指纹、冻结输入指纹和逐账户结果。[verify-daily.cjs](verify-daily.cjs)从原长期研究的固定归档读取旧引擎和相同真实行情，再与本次引擎比较：

```sh
node docs/research/portfolio-daily-20261106/verify-daily.cjs /tmp/daily-verification.json
```

核验包括63个实际十年、十五年账户：三种方法、30/30、50/50、20/40权重，零追加与每月追加，以及年度再平衡、零初始本金、期末清仓。原引擎所有非策略元数据结果逐项完全相等，包括187,893个估值点和7,729笔交易；不是采用误差容忍后判定通过。

181,233个每日快照中，181,230个可生成预算的日期都通过10,000元含费资金守恒，3个清仓日不生成预算。固定起点延长结束日期的20,331行历史快照完全相同，包含原先末日已经形成的待执行订单。

这项验证只证明增加显示没有改变既有回测，不能证明数值识别出了更好的加仓点。规则的实际贡献、失败情景、参数敏感性仍以原研究为准。

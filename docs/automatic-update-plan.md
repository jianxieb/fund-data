长衡的公开站点由仓库中的生成快照构成。`refresh.py` 只计算和检查数据，不提交、不推送；GitHub Actions 在校验通过后负责提交数据并发布同一份站点文件。另一台电脑拉取 `main` 后，可直接看到已发布的生成数据、脚本与运行规则，不依赖维护者本机的 `.tmp-*` 缓存。

## 触发方式

- [数据刷新工作流](../.github/workflows/refresh-data.yml) 每天北京时间 06:17（前一日 UTC 22:17）定时运行一次，集中更新上一交易日已公布的行情和基金净值，也可到仓库 Actions 页面手动运行。调度可能延迟，实际观察日始终取自来源。`cold_start=true` 忽略 Actions 历史源缓存；`publish=false` 仅验证，不提交或部署。只从 `main` 发布。
- [普通站点发布工作流](../.github/workflows/pages.yml) 在 `main` 的代码或文档推送后检查已提交的站点并部署。数据工作流用 `GITHUB_TOKEN` 提交时不会再次触发普通 `push` 工作流，所以它自己上传并部署刚通过验证的文件。
- GitHub Pages 发布源须为 **GitHub Actions**。两个部署作业共用 `pages-deployment` 并发组；网页只包含 `index.html`、`assets/`、`data/` 和 `docs/`，不上传原始缓存或本机日志。

## 发布门槛与失败处理

数据工作流安装 Python/Node 运行时并检查采集器语法，随后以 `refresh.py --daily` 执行九阶段刷新。独立来源并行采集；基金先批量取得最新净值及官方日收益，只补齐已验证历史之后的尾段。`portfolio` 准备单个标的的基础历史，并同步基金收益、风险和原始单位净值；用户组合仍在浏览器收到用户参数后计算。`research_funds` 复用上述已验证曲线同步扩展基金，不再重复抓取和计算。`scripts/check_refresh.py` 核对九阶段报告、严格质量错误为零、标的集合不变、历史文件哈希，以及基金/指数/股票和策略关键来源日期不倒退。基础基金的分红与拆分页归档为 `data/fund-actions.json`；新价格不会延长旧分红证据的覆盖期。

日更只执行生成数据及受影响显示契约的定向检查，并运行资源版本检查；完整代码回归留在源码推送流程。单个来源或标的失败时，保留其最后有效值与原日期，记录具体错误，其他来源的有效更新继续发布。阶段级超时或失败也只恢复该阶段拥有的数据块，报告明确标为 `partial`；不能用保留旧数据后的绿色任务证明本轮全部更新成功。缺少可保留证据、质量错误、身份变化或日期倒退仍拒绝发布。只有研究数据或来源证据变化时才提交生成文件；Actions 保留 `refresh-report.json`、`post-refresh-report.json`、质量报告、状态文件及逐阶段日志 7 天。查看失败原因应先看本次运行的 `refresh-diagnosis-<run id>` 工件，再按[维护指南](maintenance.md)定位具体来源。

Actions 源缓存只是加速：`.tmp-hist/`、`.tmp-strategy/`、`.tmp-fhsp/`、`.tmp-managers/` 和股票缓存可能被清除。冷启动手动运行不读取旧缓存；即使后续阶段失败，仍保存本轮已经取得的原始来源，避免下次重复请求。新 runner 必须能从源站重新获取或用有明确日期的仓库证据安全复算，不能把本次尝试时间冒充观察日。GitHub 对缓存有清除规则，定时运行也可能延迟、丢失或因公开仓库长期无活动被停用：[缓存说明](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching)、[定时事件规则](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)。应以实际运行报告和来源观察日判断更新情况。

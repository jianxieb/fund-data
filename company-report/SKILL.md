# 个股深入研究

## 工作流

1. 确认证券代码、交易所、币种、研究截止日。先读现有报告和变更记录。企业质量、成长阶段、价格吸引力分别判断。
2. 运行 `python3 company-report/scripts/01_fetch_data.py CODE --as-of YYYY-MM-DD`，再运行 `python3 company-report/scripts/02_compute.py company-report/data/CODE/summary.json`。根目录的 `company_report.py` 是唯一计算实现；输入输出均为 schemaVersion 2。旧 summary 不兼容，重新取数，不能手工凑字段。
3. 阅读最新公司原始公告：主要财务指标、管理层讨论、主营构成、现金流量表、资产负债表、重大事项和关键财务附注。初次覆盖补读年度审计意见、关键审计事项、关联交易、担保、重大并购及股权结构。记录实际阅读的文档、页码和未覆盖事项，不能把API数据或摘要阅读写成全文审计。每个来源分别记录报告期、公告日和全文链接；旧年报可支持历史核对，但必须另有当前报告证据。获取公告时排除摘要、提示公告、更正通知和未来公告，并保留PDF哈希。
4. 对照至少5个完整财年、最近8个单季与最新累计报告。ROE使用原报告期数值，不把中报乘二。同比区分负基数、零基数、并表、资产处置和授权款。实际数值、管理层指引、卖方预测、研究假设分栏。
5. 按 [研究口径](references/method.md) 检查盈利质量、营运资金、增长来源、行业适用的估值方法。每个关键判断对应具名证据及可观察的反证；已有负面事实放在当前判断中。
6. 更新 `data/stock-quality-research.json` 的业务论点和风险。长期优质与高质成长各有独立门槛；两者允许重叠。先研究再发布，不把初筛结果、扭亏股或红利名单批量搬入任一名单。未入选高质不能自动转入业绩爆发；须分别检验连续两季翻倍、现金转化以及周期、并表、低基数和费用影响。批量发现用 `scripts/discover_stock_stages.py`，业务复核记录与财务线索分开保存。规则见 `stock_groups.py` 和 `docs/stock-quality-method.md`。
7. 更新 `data/stock-report-research.json` 的公司分析，运行 `python3 scripts/build_stock_reports.py` 生成网页版与Markdown报告。旧报告追加具体更正和新版链接，保留原日期。列出本次改变的事实、方法、判断及仍缺的材料；无依据的旧结论直接撤回。
8. 运行相关财务计算、分组和报告构建测试。核对个股页面与报告的数据日期、分类一致。遵循项目现有发布授权和Git规则。

## 证据约束

- 同一公告的两个转载站不算两个独立来源。原始公告用于业务和财务核对，API用于结构化计算；冲突时记录具体字段、原文和采用理由。
- 数据必须含来源、公告日/交易日、报告期、单位、合并范围。截止日后发布的财报不得倒灌；历史更正数若缺当时版本，说明这是按当前已知重述数据回顾，不能用于无前视偏差的回测。
- 缺数据保留空值和具体缺口；失败重试不能用同行替代本公司，也不靠估值结论填补取数失败。
- 无可靠假设不输出目标价。不为凑页数扩写，不要求所有行业都有同样估值模型。简洁的网页结论链接到深入分析和原文。
- 每条风险说明触发条件、影响路径和下一次验证的数据。不得把归母利润仍为正、单次高增速或低PE独立当作“优质”。
